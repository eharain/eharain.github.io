    Paritas: an Oracle-compatible database built on PostgreSQL, in Oracle mode only

    Published 19 Nov 2026 · Introductions

    Paritas is an Oracle-compatible database built on PostgreSQL. A Paritas server answers in Oracle mode only. Every session, on either of its two ports, reads Oracle's SQL and runs real PL/SQL, and the mode is set when the server is made and never switched. PostgreSQL's client tools and drivers still connect, and PL/pgSQL and PostgreSQL's extensions run beside your Oracle code.

    Your application keeps its code. The SQL and PL/SQL it sends stay as they are, and only the connection string and the driver change: a PostgreSQL driver for your language works today, and Paritas drivers are coming.

    Paritas sits on top of PostgreSQL, and once it runs, PostgreSQL mode is taken off. Beneath them are the enterprise layers, which are in progress. We are building them for large transactional databases, with high availability, clustering and replication, and they will power plain PostgreSQL or Paritas on top. None of them is available yet.

    Every answer is checked against a real Oracle Database 21c, with stock PostgreSQL beside it. New this month: ROWNUM counted as Oracle counts it, LIKE and ESCAPE read as Oracle reads them, and the five REGEXP_ functions. The list of known limitations runs to more than 900 entries, and most say what to do instead.

    Paritas restores only archives that its own pg_dump made from a Paritas server. Other sources will come across through the migration tools we are building. pgrecon is step one: our free assessment of an Oracle estate runs 80 rules over it, and it is out today. The migration and development tools and the connectivity drivers are being built.

    Paritas is not for sale yet. We are aiming to release it next quarter. If you are planning a move off Oracle, we can show you the test harness running live.
